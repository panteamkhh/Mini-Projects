# Day 15 — SQL for Analysts

A `SQLAnalyzer` class that answers business questions directly in
**SQL** against a normalized SQLite database — the way an analyst
would query a real data warehouse, instead of loading one flat CSV
into pandas.

---

## Schema

```
customers(customer_id, name, region, segment)
products(product_id, product_name, category, unit_price)
orders(order_id, customer_id, order_date)
order_items(order_item_id, order_id, product_id, quantity, discount)
```

Four related tables instead of one flat file, so real joins are
actually necessary to answer anything.

---

## Business questions answered (all in SQL)

- Who are the **top customers by revenue**? (`JOIN` across all 4 tables + `GROUP BY`)
- Which **product category** earns the most? (`JOIN` + `GROUP BY`)
- What's the **monthly revenue trend**? (`strftime` date bucketing + `GROUP BY`)
- Which **customers have never ordered**? (`LEFT JOIN` ... `WHERE ... IS NULL` — an anti-join)
- What's the **average order value by region**? (subquery: per-order totals, then averaged)

---

## Key concepts used

- Multi-table `JOIN`s (inner joins across customers/orders/order_items/products)
- Aggregation (`SUM`, `AVG`, `COUNT`, `GROUP BY`)
- `LEFT JOIN` to find missing relationships (customers with zero orders)
- Subqueries (per-order totals, then aggregated by region)
- Date bucketing in SQL (`strftime('%Y-%m', order_date)`)
- Parameterized queries (`run_query(sql, params=...)`) to avoid SQL injection
- Running SQL from Python via `sqlite3` + `pandas.read_sql_query`,
  the same pattern used against any real production database

## Dataset

`data/sales.db` is generated by `generate_data.py`: 40 customers, 12
products, 350 orders, ~900 order line items — with 5 customers
deliberately left order-less so the "customers without orders" query
has real rows to find.
